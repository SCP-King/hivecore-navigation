## 一、本次核心问题：集成时 SLAM 自带 TF 与系统 TF 冲突（HC-INT-001）

### 1.1 冲突现象（此前已现场确认）

甲方 Hive2 运动栈与 GUI-SLAM 同时运行时，`/tf_static` 上存在 **2 个 `robot_state_publisher`** 对同一条静态 TF 发布不同值：

| 发布来源 | 入口 URDF | `base_footprint→base_link` Z | 模型 |
|---|---|---|---|
| 运动栈 | `hive2.config.xacro`（/opt/hivecore/hive2-motion/1.0.0） | **0.900 m** | 24 link 带腿带轮（正确模型） |
| GUI-SLAM | `hivecore_robot.urdf.xacro`（release_slam_3d） | **0.300 m** | 3 link（base_footprint/base_link/lidar_link） |

现场 `tf2_echo` 同一条 TF 的 Z 值在 0.300/0.900 之间交替 → 坐标系一致性无法保证，已记录于 `docs/甲方问题记录2026_10_13.md`（HC-INT-001）。

### 1.2 定案（甲方/用户确认）

> SLAM 开发有自身的 TF，集成到机器人时与系统 TF 冲突；**只保留系统 TF**，在 launch 文件里注释掉 SLAM 自带 RSP 即可。

### 1.4 注释掉后**只禁用了什么**（本次勘察结论）

- **只禁用** SLAM 自带的 `robot_state_publisher` 节点（唯一启动它的就是这段 include；`hivecore_robot_description` 是纯资产包，无其他执行节点）。
  - 副作用：`/robot_description` 话题从 2 个发布者变为 1 个（只剩运动栈 24-link 正确模型），对 RViz 反而是修正。SLAM 栈内（slam3d / cloud_preprocessor / GUI）**无任何节点消费 `/robot_description` 话题**（已 grep 确认），不受影响。

### 1.5 被保留的必需行为（未受影响）

| 组件 | 生命周期 | 仍需 | 依据 |
|---|---|---|---|
| `static_tf_publisher_node`（lidar_link→imu_link→livox_frame） | `cloud_preprocessor.launch.py` 独立 include | 保留 | 静态外参边，不属于冲突面 |
| `lidar_cloud_preprocess_node`（/livox/lidar/geo_filtered） | 同 cloud_preprocessor | 保留 | 点云输入 |
| IMU complementary filter | `include_desk_prelude` 内第一个 include | 保留 | 只注释了第二个 include |
| `slam3d_node` | `slam3d.launch.py`/mapping/localization include | 保留 | 定位/建图 |
| 系统 TF 链 `base_footprint→base_link→lidar_link` | 运动栈 hive2_driver RSP（/opt/hivecore） | **保留** | `quad_leg_description/urdf/hivecore_sensor_frames.xacro:9,21` 明确本链由 hive2_driver RSP 提供 |
| map→base_footprint 动态 TF | `slam3d_node` 定位有效后 | 保留（前置：GUI 定位） | 与 RSP 无关 |

### 1.6 运维注意事项

- `release_slam_3d` 非 git 仓库，本次为对 install 运行副本的直接注释；若甲方重新部署/覆盖该目录，需重新执行本修改（或随升级一起处理）。
- 若存在**不启动运动栈**的纯 SLAM/回放场景（`replay_rosbag.launch.py`），系统 TF 未必在发，届时需临时恢复该 include（文件中已注明）。

## 四、待办 / 未决项（不宣称为已解决）

1. **`ground_z` 变化**：阶段二实测稳定在 0.844–0.871（method=robust_z_percentile），而阶段一同方法观测约 0.257。两次运行数值都稳定但地面高度差约 0.6 m，可能为机器运行间被移动/姿态差异，也可能为 ground_filter 判地算法问题 → 归入 ground_filter（Jacobi 最小特征向量 / RANSAC）独立待验证风险队列；未做运动验证前不用于避障，不视为"对齐通过"。
2. **S4 对齐验收**：需要真机只读、低速移动下做（观察移动中原点连续性、无 RESET 跳动、占用网格不漂移），并顺带复测 `ground_z` 归属。乙方不主动移动机器人、不发布 `/cmd_vel`。
3. **数据源铁律**：所有 frame/TF/话题只能来自甲方发布内容 + 参数文本.txt 人工测量值，乙方不凭空生成；GUI 前置话题（如 `/robot_pose`、`/localization_status`）必须在 launch/日志/脚本里显式提醒用户。TF 变更必须做全仓关联性闭环审计（声明、lookup、配置、launch 覆盖、install 运行副本、下游消费者）。
4. **主指令宏**：terraform/harness 级约束——命令超时/失败立即停止不重试；统计汇总命令清单交由用户判断执行。
