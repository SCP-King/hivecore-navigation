# M1 启动与数据自检流程（可重复执行 SOP，2026-10-13）

这是乙方 hivecore-navigation M1 阶段的**可重复执行流程**。每一步含目的、命令、判定标准。
所有「数据就绪」判定都是**真实订阅采样**（甲方 publish_only_when_subscribed 的库必须实际订阅）。
本流程**不驱动底盘**；最后半步（真机）留待甲方修复双 RSP 后。

---

## Step 0. 前置：ROS 环境

乙方工程根：`/home/demo/lyy/hivecore-navigation`

```bash
export ROS_DOMAIN_ID=55          # 甲方现场域（与运动栈/GUI-SLAM 一致）
source /home/demo/release_slam_3d/setup_runtime.sh   # 甲方 overlay（含 rclpy 动态库路径）
```

## Step 1. 检查甲方运动栈（底盘 + Livox）

```bash
bash scripts/start_hivecore_deps.sh
```
或手动：
```bash
ps -ef | grep -E "hive2_(driver|controller)\.launch|livox_ros_driver2"
```
- 判定：`hive2_driver.launch.py`、`hive2_controller.launch.py`、`livox_ros_driver2_node` **都在跑**
- 不在 → 甲方启动：`start_hive2_motion.sh`（本脚本 `--start` 可代启，需显式授权）

## Step 2. 检查/启动甲方 GUI-SLAM

同 `start_hivecore_deps.sh`。未运行且需 geo_filtered / livox_frame TF 时启动（与桌面一致）：
```bash
source /home/demo/release_slam_3d/setup_runtime.sh
ros2 launch hivecore_console_slam3d gui_slam_console.launch.py use_sim_time:=false
```
- 判定：`static_tf_publisher_node` + `lidar_cloud_preprocess_node` 在跑
- 若 M1 只用原始 /livox/lidar + 甲方确认 livox_frame TF 由运动栈提供，可暂不启 GUI-SLAM（本工程 now 启用原始点云 + static_tf 链）

## Step 3. 乙方全量自检（真实订阅）

```bash
bash scripts/preflight_hivecore.sh
```
覆盖检查项与判定（输出带 [PASS]/[FAIL]/[WARN]）：
| 检查项 | 判定标准 | 结果示例（2026-10-13 现场） |
|---|---|---|
| ROS_DOMAIN_ID | =55 | PASS |
| 甲方进程 | motion + GUI-SLAM 在跑 | PASS |
| /odom | 真实订阅 ≥20Hz | PASS ~70Hz（244帧/3.5s） |
| /livox/lidar | 真实订阅 ≥2Hz | PASS ~11Hz（40帧/3.5s） |
| /livox/lidar/geo_filtered | 真实订阅 ≥2Hz | PASS 44帧/3.5s |
| QoS | rel→be 兼容 | PASS |
| TF base_footprint→base_link | 可解析 | PASS（但 z 双定义→见冲突项） |
| TF base_link→livox_frame | 可解析 | PASS [0.295,0,0] |
| **双 RSP 冲突** | /tf_static 发布者<2 且 z 唯一 | **FAIL**（发布者=3，z∈{0.3,0.9}） |

- 全部 PASS → 进 Step 4
- 有 FAIL → **停止**，按输出处理（甲方启动命令/双 RSP 处理建议），修复后重跑

## Step 4. M1 干跑（不驱动底盘）

```bash
bash scripts/run_m1_safe.sh
```
- 内部：Step 3 preflight → 通过后以 `gate_cmd_out:=/cmd_vel_dryrun` 启动导航整链
- 判定：导航各节点起来，/cmd_vel_dryrun 出现速度输出（用 RViz 下发目标后），底盘**不动**
- preflight FAIL 时 **`.sh` 自动拒绝**，node 不启动

干跑验证的控制序列观测：
```bash
ros2 topic echo /cmd_vel_dryrun --qos-reliability reliable   # 应见非零 vx/vy/omega
ros2 topic echo /curr_state --what               # 应随 /odom 变化
ros2 topic hz /local_plan                        # MPC 更新率
```

## 故障日志与本流程内的含义

| 现象 | 归因 | 处理 |
|---|---|---|
| preflight [FAIL] /odom 无发布者 | 运动栈未起 | 启动甲方运动栈 |
| preflight [FAIL] TF base_link→livox_frame 不可用 | GUI-SLAM 未起 | 启动 GUI-SLAM（static_tf） |
| preflight [FAIL] 双 RSP | 运动栈 z=0.9 vs SLAM 栈 z=0.3 双定义 | **甲方**确认几何+停用其一 |
| /robot_pose 存在但无数据 | GUI 未进 localization（Idle enable_processing=false） | M1 不依赖；真机需 GUI Load map→Start |
| 导航起来但 /cmd_vel_dryrun 零速 | gate 未放行 | 查 gate logger / /gate/status；M1 需 gate_require_slam:=false |

## 复跑要点（可重复性）

- 所有脚本幂等：`start_hivecore_deps.sh` 检测已运行实例，绝不重复启动甲方。
- `preflight_hivecore.sh` 无副作用（只订阅/echo/tf2_echo），可反复执行。
- `run_m1_safe.sh` 默认 dryrun，绝不碰 /cmd_vel。
- 每次恢复前先 `pkill -f dynacbf_real.launch.py`（清乙方残留），再重跑 Step 3→4。
