# 2026-11-11 轨迹有效期修复与短距离实机测试

操作者已确认现场测试区域无人、无障碍，并可急停；授权最高 0.03 m/s、
移动不超过 0.2 m。本轮进一步限制软件累计行程为 0.10 m，12 秒超时。

## 修复

- 监控器按 B 样条原始 start_time 和 duration 检查有效窗口，每次重放重新
  检查位姿/关节反馈；不再将正常的单次轨迹事件误当成必须 1 Hz 更新的心跳。
  重放不会修改原始轨迹时间，过期/非法轨迹仍清空。
- 慢速执行器改为检查系统健康 navigation_ready，要求轨迹候选与反馈通过；
  对位姿、路径、局部里程计做帧和时间检查。
- 增加累计里程、指令距离积分、会话超时限制。到限后锁定停止，不自动重启。
- 增加显式 enable 话题，允许执行器先禁用上线，再生成新轨迹和使能。
- 手动目标模式中，轨迹名义时间结束而实测位置尚未到目标时，从里程计重规划，
  避免低速跟随尚未到点即将任务标为完成。

## 实测

只规划预检连续 4 秒收到 501 点路径，无此前约 1 秒后清空现象。
首次执行尝试因订阅上线时轨迹时间不足，保持零速，未形成有效行驶。
第二次采用先禁用上线、再生成目标与使能的流程：

- 最大平移速度指令：0.0299279 m/s。
- 底盘 /odom 累计里程：0.101936 m。
- 执行器到限进入 SESSION_COMPLETE，输出零速并退出。
- 停稳后 3 秒采样，70 条里程计消息最大反馈分量约 0.000650；测试执行器
  已不在 /cmd_vel 发布者中，原底盘和跟随接口保留。

该结果是里程计报告的短距离移动；不是完整路线自主导航或物理安全验收。
当前运动执行器退出，甲方定位与规划链保留。未再次执行扩大距离测试。

测试脚本 `scripts/n01_bounded_motion_test.py` 默认仅规划；只有显式 `--execute`
才启用这段有界测试。它不是常驻行驶入口。执行器结束时父脚本再次发送零速。
