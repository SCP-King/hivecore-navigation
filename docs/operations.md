# 运行与操作

## 启动与管理边界

仓库根目录执行 `bash scripts/n01 gui`；默认页面 `http://127.0.0.1:8123`，ROS domain默认55。桌面GUI入口为 `apps/n01_slam_gui/run_slam_lite_gui.sh`。脚本分类见 [脚本说明](../scripts/README.md)。

GUI启动只创建界面和ROS监控，不自动启动SLAM、导航、RViz或底盘。先从桌面入口启动底盘/雷达/遥控/RSP，GUI不补起第二套驱动或RSP；退出只清理自己拥有的进程。节点管理分类展示当前节点、重名、归属，重名不是任意杀节点的依据。

## 后端与地图模式

| 后端/模式 | 操作 |
|---|---|
| 甲方SLAM3D Lite／离线地图 | 建图结束保存PCD（有地图可跳过）→ 启动定位 → 加载PCD → 初值匹配 → tracking → 启动导航 |
| FAST-LIO2／离线地图 | 选择PCD → 启动定位 → 初值ICP → tracking → 启动导航；更换地图先停止后端 |
| 两个后端／实时地图 | 启动本次实时SLAM（同时建图和估计位姿）→ 同步地面 → 手动启动导航；不另加载旧PCD或开启一套定位 |

“离线”是已保存PCD，仍使用当前传感器；“实时”是本次SLAM地图。bag是历史记录，可用于离线重建、参数/时延回归和复现实验，不能代替当前障碍和位姿。定位页bag检查只核验文件/话题元数据，不自动回放。运行中锁定后端/模式选择，停止后再切换。

同步地面使用当前地图实际平面，不把map的z=0当成地面，不跨地图复用标定。确认地图与实时云重合，机身参考点高于地面。同步失败先核对地图、雷达外参与站姿，查看具体数值，不能仅通过降低阈值掩盖错误坐标。

## 两种导航任务

**地图选点**：点击地图或输入map目标，发送并查看SCAN结果，另点“开始沿路径行驶”。GUI请求控制器后先保持disabled，由控制器检查自己的执行依据再启用；发目标、打开RViz不会直接驱动车轮。GUI不再独立起旋转进程，大转向与边走边转由统一控制器处理。

**手动记录路线**：新建路线 → 遥控到真实A点停车 → 记录位置、朝向、名称、停留 → 到B等点重复记录 → 结束保存。必须至少A、B两个真实停车点；每站保存原始时间、四元数、定位、里程计和关节状态。记录要求真实停车与新定位确认，不把预测值或手填坐标冒充实测节点。

开始路线会先回到原A的位姿状态，再逐站到终点；每站完成位置、朝向、停稳和真实定位确认后才计停留，默认1秒。整个路线复用一个控制进程。可暂停、继续、取消；暂停保留当前站点及剩余停留，继续重新请求该站，失败不跳站。用“结束当前任务”统一清理旧任务后切换模式。

离线路线绑定PCD内容和坐标模型；实时路线绑定当前SLAM会话，保存后仅能在该会话继续回放，重启SLAM不能跨会话复用。需要跨次使用时保存地图、进入该地图定位后记录路线。路线管理支持加载、查看、刷新、删除；运行/暂停中的路线须先取消才能删除。

## 连续运行与速度

当前主链只启用SCAN，CBF开关明确禁用，后续另作专项验收。默认前进vx≥0、vy=0，头沿路径；侧后方目标可进入同一控制器ALIGN，实测停车后检查真实URDF旋转扫掠和全向雷达。旋转受阻向SCAN请求绕行，不忽略碰撞。纯控制横移工具仍是显式实验入口，不随导航启动。

速度字段0.01～0.8m/s；改变速度后重启导航，保持审核与控制一致。0.8是配置上限，未作实机验收；实际速度受场景覆盖、制动距离、反馈质量、轮速和舵速影响。原始odom位置的两倍异常未在桌面底层修复，导航统计使用测量twist积分，不据此宣称真实尺度已标定。

短时全局定位迟到由同一状态桥的有界里程计预测衔接，不重盖时间戳；预算耗尽、场景失效、真实运动学/碰撞风险仍停车并给原因。手动实际流量（包括零速）立即让权，闲置发布者不阻止自动启动。手动/急停不自动抢回；用户明确继续后重新检查。

## RViz、地图和提示

建图、定位和导航各有RViz入口；定位可用2D Pose Estimate手动重定位。导航Path是显示，不是独立执行许可；控制器运行时显示其实际保持段，未运行时显示SCAN提案。调试全局参考线可单独打开。

GUI主地图是一个图面加模式下拉框，支持自动或固定建图/定位/导航。青绿为当前障碍、灰蓝为参考、紫色为实际URDF包络、白色为实体、琥珀为环境6cm名义余量；不是三个大圆。蓝线显示 `/planning/global_path` 完整参考，青线叠加 `/n01/navigation/path` 当前执行前段；参考线不会充当执行许可。超出当前视野时调大地图范围。后台生成URDF投影和栅格/PNG，重复路径心跳不触发几何刷新，相同图片不重复发送；日志最多保留300条显示行。事件循环只提交最新帧。数据过期隐藏对应层，不冒充实时。

启动结果和任务最终结果提示5秒自动关闭；运动中间状态仅写日志。任务状态与规划状态分开，路径就绪不代表反馈永久有效。报告成功只在真实到达确认后产生，进程退出或旧站ARRIVED不算本站成功。

导航当前保留拟合地面以上 **3cm** 的障碍点，栅格分辨率 **5cm**。3cm是过滤门槛，不是实测可靠识别下限；小盒子、低台阶还受地面拟合、距离、遮挡与回波影响。预处理的高度范围相对base_link，不能直接当成离地高度。

**导航地图显示（2026-11-17）**：地图区拆成"地图内容"（自动/导航/建图/定位）和"渲染方式"（低耗栅格/细节点云）两个选择，默认 **自动 + 低耗栅格**。低耗栅格优先订阅规划节点的 `nav_msgs/OccupancyGrid`（`/grid_map/reference_grid` 静态参考层、`/grid_map/live_grid` 实时层，5cm、-1/0/100、5Hz、transient_local）；建图/定位没有栅格时，用 numpy 直接把点云投影成栅格，不走形态学与距离变换。三种内容使用不同参考色：导航灰蓝、建图浅蓝、定位淡紫，实时层统一青绿；**已知空闲为深蓝、未观测为近黑**，所以占据栅格不会因为大部分区域空闲而看起来全黑。只有选"细节点云"时才使用原来的发光/膨胀渲染。栅格无占用数据或过期时自动回退点云，不会显示全黑。该栅格是三维体素的**只读二维投影**，不参与规划。

**GUI 停止节点的权限边界（2026-11-17 调整）**：默认只停止由当前 GUI 登记的专属进程组。节点体检页勾选"允许停止外部进程"后，可以停止终端启动的 N-01 节点（`scan_planner_node`、`n01_navigation_controller`、监视器、`n01_static_map`、`n01_robot_footprint` 等），也可以在输入框里直接写节点名（至少6字符，按命令行匹配）。甲方保护名单始终生效：底盘、腿控、手柄、Livox、lpms、ethercat 等即使同名也不会被停止。停止顺序为先 SIGINT 所在 launch，3秒后对残余 SIGKILL；外部进程被停后，原启动终端可能立刻重新拉起，需自行确认来源。

更新后正常停止旧GUI所属任务、导航和SLAM，再重启GUI及相关模块；不用重启桌面底盘/RSP。默认甲方运行库 `/home/demo/lyy/slam3d_lite_20261106_test`，各入口共用 `scripts/lib/slam_runtime.sh`；缺失时明确报错，不自动换旧库。`SLAM_ROSK`可明确指定其他版本。

**故障原因显示（2026-11-17）**：GUI 不再直接显示 `scan_optimizer_no_collision_free_solution` 这类内部代码，统一翻译为简短中文（如"局部优化找不到无碰撞轨迹"）。动态的起点包络原因会带坐标（"起点包络被实测障碍挡住（x, y, z）"）。未登记的内部代码显示"未登记原因（详见日志）"；外部发布者名称与任意文本原样显示并转义。原始代码仍保留在日志与"运行流程"展开明细中，供排查。

## 原始扫描过期与残留导航（2026-11-18）

“启动实时SLAM”只启动建图、位姿适配及点云桥接，导航规划仍需单独点击“启动导航”。检测到已有导航实例时，界面提示其PID；不会自动重启或接管该实例。重启SLAM会建立新坐标会话，旧导航须从原入口停止，再为当前会话重新启动。

占据图的消息接收心跳不代表新扫描：`/grid_map/occupancy`保留实际处理的原始扫描时间。若该时间持续过期，先检查`/cloud`、`/cloud_map`和`/body_pose`的发布者及源时间，不能通过重写地图时间戳或单纯放宽时限来修复断流。自动选图按原扫描有效性判断导航是否正在更新；手动选择导航地图时，过期数据标为历史缓存。全部未知的栅格不作为有效画面，已有空闲格而没有占用格的栅格可以显示。

GUI未持有的导航实例不会因退出GUI而被停止；“停止导航”未执行时必须显示未停止，不能报告停止成功。可从实际启动入口运行`bash scripts/n01_navigation.sh stop`管理本仓库导航，桌面底盘、雷达与遥控仍独立管理。
