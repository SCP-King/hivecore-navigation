# 运行与操作

## 启动与管理边界

仓库根目录执行 `bash scripts/n01 gui`；默认页面为 `http://127.0.0.1:8123`，ROS domain默认55。桌面GUI入口应指向 `apps/n01_slam_gui/run_slam_lite_gui.sh`。脚本清单见 [脚本说明](../scripts/README.md)。

GUI启动只创建界面和ROS监控worker，不自动启动建图、定位、导航、FAST-LIO2、RViz或底盘。桌面底盘启动入口独立，提供原有驱动、遥控和RSP；GUI不补起第二套驱动/RSP，也不清场杀死外部节点。停止或退出仅清理GUI拥有的进程，归属由PID和启动时刻核验。节点管理页用于分类查看当前节点、重复名称和归属；重名本身不是任意杀节点的依据。

先从桌面启动底盘/雷达，确认反馈和模型正常，再开启GUI，手动选择模块。甲方前端与自部署FAST-LIO2经同一适配器进入导航。FAST-LIO2区分离线地图定位与实时建图导航；切换前结束旧任务，保持规范位姿与地图一致。

## 建图、定位、导航

1. 建图：选择后端，手动启动，检查实时点云、IMU、地面参考；按需要录包。结束保存后核对确切PCD路径。
2. 定位：选择地图并加载，使用GUI/RViz设置初值，进入tracking，核对地图与实时云。tracking是会话状态，还需查看时间戳、预测状态及导航READY。
3. 导航：同步PCD与地面后启动导航。地图/安装模型切换后重新检查，不复用其他地图的地面参数或旧路线。
4. 运动：规划成功后另点“开始沿路径行驶”；发送目标或打开RViz不直接驱动机器人。使用“结束当前任务”统一取消当前模式的运行、暂停或等待状态，再切换目标/模式。

导航速度字段支持0.01～0.8m/s；提高后重新启动导航，使规划器、轨迹复核和执行器一致。0.8是可配置上限，尚未实机验收；实际指令还受制动距离、反馈和轮组约束。不要将Twist上限或原始odom累计路程直接当成独立实测速度/距离。

## 两套定位后端与数据加载

| 后端 | 使用已有地图定位的顺序 |
|---|---|
| 甲方 SLAM3D Lite | 启动定位节点 → 加载PCD → 初始位姿 → 匹配成功 → 进入tracking |
| 自部署 FAST-LIO2离线地图模式 | 先选择PCD → 启动定位 → 初始位姿触发ICP → 匹配后自动tracking；更换地图需停止后端 |
| 自部署 FAST-LIO2实时模式 | 不加载历史PCD，使用本次建图地图；无需历史bag |

“离线地图”表示预先保存的地图，在线定位仍接收当前雷达/IMU。bag是历史传感器记录，不能与当前实时位姿混为同一个输入。定位页“建图bag”折叠项仅核验元数据、数据文件存在性、消息计数及输入缺项，不执行回放，也不证明所有数据无丢帧或与PCD自动对应。独立回放/重新建图使用隔离入口。运行中禁用后端与模式切换，停止当前链后再选。

## 两种导航模式

**地图选点移动**：点击地图或输入map目标，发送并确认，等待本次全局和局部路径有效，再开始行驶。旧目标路径即使刚重发也不能作为新目标结果；终点不匹配时等新路径或明确超时。

**手动记录路线**：新建路线，遥控到点停车，记录名称、位置、朝向、停留时间；每站还保存原始位姿时间戳、完整四元数与协方差、定位状态、实测里程计速度、关节位置/速度及其时效。记录时要求反馈确认停车；关节快照用于核对，不直接恢复为执行器命令。可撤销末点或放弃草稿。记录使用两次间隔350ms的新鲜真实定位，位移超过2cm/转角超过3°时拒绝。结束保存后加载路线，点击“开始运行路线（先到起点）”：先到第一个记录点，再依次访问其余点；可选末站后返回首点。中间日志记录进度，仅最终结果通知。

新录制路线必须至少包含A、B两个真实停车节点，并校验目标位姿与保存的实测状态一致。每站默认停留1秒，可修改。浏览器刷新或重新连接保留本GUI进程中的草稿、已加载路线和编辑互斥状态；退出GUI前仍需结束保存，未保存草稿不保证跨进程重启恢复。保存完成后，机器人可以由遥控器移到其他位置；执行仍以已保存的首点为起点。保存不依赖当前位姿新鲜度，加载预览只需有效PCD；实际执行独立检查定位与实时感知。

路线预览显示先到首点、站间直线距离、逐站停留时间及末站后是否返回首点；距离是站点间距，不是绕障后的实际行驶长度。

路线位于 `/home/demo/lyy/n01_runtime/routes/`，绑定地图路径、内容SHA256、机身参考帧和传感器几何摘要；地图/模型变化后拒绝执行。列表支持刷新、详情、加载、删除。删除前确认，文件移入 `.trash/`，拒绝目录逃逸及符号链接。运行或暂停路线须先取消才可删除。记录、编辑和自动执行互斥。

新保存路线每站：重新规划 → 保持当前机身朝向平移到点 → 零速及真实定位确认 → 对齐站点朝向（完整扫掠检查）→ 停留 → 下一站。历史路线缺少朝向时机字段时保持先对齐再平移的兼容行为。失败不跳站；任务ID和目标绑定排除旧到达反馈。暂停保留站点与剩余停留，继续时重新检查并规划；取消清空任务。手动接管/急停不自动恢复运动。

## RViz与故障处理

建图、定位、导航各有独立RViz入口：`rviz/n01_mapping.rviz`、`rviz/n01_localization.rviz`、`rviz/n01_full_pipeline.rviz`。保留定位 `/initialpose` 与导航 `/move_base_simple/goal` 工具。默认突出唯一执行路径 `/n01/navigation/path`；全局参考和局部候选属于调试层。地面不强制显示为z=0。

| 现象 | 检查和操作 |
|---|---|
| 规划成功但不运动 | 查看执行器状态、READY、手动源、停车锁存、轮组反馈和当前有效前缀 |
| 提示上个任务未结束 | 点击“结束当前任务”，等待所属执行器退出，再切换模式/重新选点 |
| tracking但断续停车 | 查看原始定位年龄、预测模式、里程计/点云时效；超限应停车，不能仅看绿色tracking |
| `scan_ref miss after 250 ms` | 甲方LO参考轨迹未及时配对；导航短时预测可衔接，持续异常仍需上游修复 |
| 同步地面失败 | 核对地图、机身位姿和可见地面；不要填0或固定0.9绕过；共享拟合会排除天花板候选 |
| 缺少wheel_link到map TF | 检查真实CAN轮反馈转换、joint_states与唯一RSP，不添加假轮角/竞争静态TF |
| 未检测到底盘RSP | 从桌面恢复底盘模型及ROS通信，保持“不启动SLAM RSP”，不再起一份模型掩盖问题 |

本轮预测与GUI路由修改需要重新加载相关进程：先结束运动，再正常重启GUI及其定位/导航模块，重新进入tracking；底盘和雷达入口不需要为本次代码修改重启。验证状态见 [验证文档](validation.md)。


2026-11-14现场恢复记录：雷达和唯一桌面RSP先后出现进程仍在、DDS接收队列堆满但新参与者收不到数据。经单独授权，分别恢复原参数进程，并仅为这两个进程采用运行目录私有CycloneDDS依赖；底盘和遥控保持原样。桌面入口文件未修改，重新完整启动桌面入口会恢复原通信配置，不能把本次恢复当作入口已永久修复。GUI不得自动照此重启外部节点。排查应同时检查真实消息、TF和队列，不能仅凭PID判定在线。


项目入口现已接入进程级通信选择（`N01_RUNTIME_RMW`，默认auto）。当前机器的私有CycloneDDS依赖存在，重启GUI及建图/定位、导航后将用于项目节点；这是项目入口的持久化修改，桌面雷达/RSP入口仍未修改。启动时日志输出GUI选择的RMW。需要回退时从终端以 `N01_RUNTIME_RMW=rmw_fastrtps_cpp` 启动GUI；直接使用ROS launch会沿用调用终端环境，应自行明确RMW。依赖缺失不会自动下载，auto模式会警告并使用现有RMW，明确要求Cyclone而依赖缺失则拒绝启动。


通信选择范围补充：点云感知采用auto优先Cyclone；涉及真实控制权GID识别和底盘参数服务的执行器、纯控制工具、轨迹可行性监视固定为已验证FastDDS。不能给所有节点统一套用同一RMW后直接宣称可控制。相关修复加载无需改动桌面底盘启动脚本。


GUI主地图使用单一图面及右侧模式下拉框。自动选择顺序为新鲜导航健康数据对应的导航视图、当前运行的建图视图、跟踪/重定位视图；也可固定选择建图、定位地图、导航栅格。导航未就绪不等于导航未运行，阻塞时仍显示导航环境。FAST-LIO2 mapping/realtime同样参与自动切换。地图使用当前控制位姿跟随机器人，融合历史参考和新鲜 `/cloud` 实时点云，0.2秒检查重绘，缓存无变化时不重复编码。输入发布频率仍决定信息更新频率，2秒全局地图不会被伪装成逐帧数据。

青绿实心及局部光晕显示实时障碍，灰蓝显示参考环境，青色三圆按实际比例显示机身覆盖，红色提示二维投影占用与机身包络重叠。光晕仅是显示效果，不改变规划膨胀。只弥合单栅格采样间隙，不根据地图包围框推断整片空闲区域。规划路径、历史轨迹及目标点覆盖在同一地图；地面拟合有效时显示使用实际拟合地面。预览使用既有现场点云离线生成，未控制机器人运动；完整浏览器交互外观仍需用户重启GUI查看。


机器人图层更新：从桌面RSP发布的 `/robot_description` 解析collision几何，并根据 `/joint_states` 和机身roll/pitch/yaw计算当前地面投影；白色为实体、深色为轮子。不用固定矩形替代关节姿态，缺少必要关节或存在未支持mesh明确显示模型未就绪。当前URDF为box碰撞体，额外支持cylinder/sphere；当前实机快照成功投影17块碰撞几何、16个关节。

紫色光晕是轨迹审核反馈planning_footprint指定的当前机器人侧包络（三圆并集，含体素/采样及复用偏差余量），不将URDF实体假称为已用于所有规划计算的形状。琥珀色取 `/grid_map/occupancy_inflate` 的当前机身高度切片，代表规划器实际环境膨胀；青绿仍为实际观测障碍。两类膨胀属于不同计算环节，界面不把它们作为需要再叠加的额外膨胀。数据过期隐藏相应包络并显示等待，不使用估计默认图形。需要重启GUI及导航加载新显示和审核字段，桌面RSP/底盘无需重启。


环境外扩与机器人侧图层现已分开：琥珀色订阅 `/grid_map/environment_inflate`，仅表示环境名义6cm余量，受5cm栅格离散影响；紫色表示机器人基础覆盖，白色为URDF实体。旧 `/grid_map/occupancy_inflate` 是包含机身尺寸的中心禁入区，不再用于GUI琥珀环境层。需重启GUI及导航加载，桌面底盘/RSP参数不变。


GUI页面生命周期：主入口显式注册 `/` 页面，ROS worker只在进程启动时启动。每个NiceGUI客户端独立保存控件、图表缓存及地图点击坐标；刷新/重连创建新页面，不复用已删除Client的Element。页面删除时取消本页定时器和仍在操作页面的异步任务，异步任务继续沿既有取消清理逻辑退出（例如GUI路线执行协程取消后停车）；不会将浏览器页面删除等同于整个GUI进程退出，也不会据此清理桌面底盘/RSP等外部节点。最终结果通知在页面失效后不再创建控件，后台日志/ROS状态仍由进程级对象维护。

## 甲方运行版本（2026-11-15）

默认采用 `/home/demo/lyy/slam3d_lite_20261106_test`。GUI、SLAM、导航和纯控制入口共用 `scripts/lib/slam_runtime.sh`；`SLAM_ROSK` 可显式覆盖（回退旧版：启动GUI前设置 `SLAM_ROSK=/opt/slam3d_release`）。工作区只通过 `install/local_setup.bash` 叠加，避免重新引入构建时记录的旧甲方目录。缺少指定版本时直接报错，不自动换版本。

雷达标定、地面、建图/定位参数、MOLA等待优化继续使用项目配置，地图仍由GUI选择。`launch_robot_state_publisher=false`保持强制约束：模型由桌面底盘入口唯一发布。切换版本需正常停止原GUI所属SLAM/导航后重启GUI，不修改或重启桌面底盘、Livox和遥控。GUI启动仍只启动GUI及监控，建图/定位/导航须显式操作。

导航启动会一并启动 `n01_robot_footprint`，不需要手动维护三圆半径。它只读桌面URDF和腿姿，导航停止时一起退出。GUI显示紫色URDF转向包络、白色当前实形、琥珀色环境裕量；缺失URDF或腿姿会明确报告模型不可用，不缩小模型放行。轮转全角度已被包络覆盖，不要求先启动轮转关节转发节点。

GUI地图渲染在后台线程执行栅格化、包络绘制和PNG编码，网页事件循环只提交最新图像；每个客户端最多一个渲染任务，慢帧期间合并刷新请求，不累积过期帧。环境图层先裁剪到视窗、合并重复像素；日志每轮最多推送80条，避免一次排空队列阻塞连接心跳。修改需重启GUI加载；运行中建图应先正常保存和停止，再退出GUI。
