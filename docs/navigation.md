# 导航算法与位姿连续性

## 链路和唯一执行路径

`建图/定位后端 → 规范适配器 → 时间对齐导航桥 → SCAN全局/局部规划 → 原生四轮复核 → 统一路径 → 显式启用的执行器`。

全局参考 `/planning/global_path` 与局部候选 `/n01/live_navigation/hive2_candidate_path` 为内部输入。`/n01/navigation/path` 是对外路径：局部已验证段替换当前全局对应部分，再拼接剩余全局后缀。要求同地图、同目标、时间有效、接续间距不超过0.30m、方向夹角不超过60°。状态携带路径时间戳和有效前缀点数；执行器只在有效前缀选预瞄点，前缀耗尽时等待新局部段，不回退到未验证全局后缀。

全局参考随实时环境刷新，局部窗口每0.5秒触发重规划，碰撞可更早触发；消息重发频率不是实际几何改路频率，也不是动态障碍响应延迟。

## 静态参考与实时障碍

当前标准导航启用 `grid_map.static_prior_as_cost=true`：局部窗口内静态PCD作为全局A*软代价，代价倍率12；实时占用始终是硬碰撞约束。窗口外静态先验继续硬约束。局部优化与旋转检查采用有效实时占用层，静态参考不再单独阻塞身边已变化的场景。原PCD不修改。

配置仍保留严格静态模式。`static_observation_refresh=true`时，自由射线必须至少3次唯一递增扫描且跨度≥0.3s，间隔≤0.6s；1.5s证据过期恢复先验。新命中立即撤销自由证据，同帧命中优先。3D体素与XY列证据覆盖历史障碍和地面射线高度不同的情况。地面返回参与自由射线，但不标作占用。静态缓存只在必要时刷新，膨胀合并重叠Z区间。

实时未知/遮挡空间不等于已证空闲；静态参考模式不能证明所有未观测位置可通行。完整包络、实时点云门控和已验证前缀继续保留。地图与地面定义见 [坐标模型](coordinates_and_chassis.md)。

## 延迟定位：测量预测和真实纠偏

实现文件：`delayed_pose.py`、`twist_odometry.py`、`live_scan_bridge.py`。预测参数及观测门限持久化在 `config/live_scan.yaml`、定位和导航launch默认值中。

1. 保留原始SLAM位姿及源时间戳，不用当前时间冒充新测量。
2. 原始 `/odom` 的位置增量历史上约为其速度积分的两倍。导航内部改用**测量到的机体线速度**，按原始时间间隔及odom姿态旋转到里程计坐标，以梯形积分重建平移；姿态沿用测量odom姿态。只改变导航内部缓存，不修改原始odom、轮径、底盘参数或桌面进程。
3. 延迟真实定位到达后，插值取得其原始时间戳对应的局部里程计，将该定位传播到当前测量时刻；与此前预测比较后，平滑更新修正历史。这里的历史插值用于时间配对，向当前的推算依赖实测运动，不是凭最后速度无限外推。
4. 当前 `/body_pose` 和扫描时刻 `/scan_body_pose`、点云采用同一因果修正历史。扫描时间戳不改；不拿最新TF替代扫描时刻TF。旋转原始雷达云使用时间匹配的预测机身位姿与机身至传感器外参，避免继续依赖迟到的map→body TF。
5. 新定位造成的修正从此前预测连续开始；默认最短0.8s，修正平移速率≤0.04m/s、角速率≤0.08rad/s。参数是修正项的速度，不是车辆速度限额。绕有效机身参考点插值，避免远处odom原点放大旋转误差。

| 约束 | 默认值及行为 |
|---|---|
| 原始定位预测时限 | 5.0s，源时间戳和接收年龄均受限；重复/乱序定位不延长有效期 |
| 锚点后位移/转角 | ≤0.12m / 0.20rad，独立于时限；高速下会更早耗尽预算 |
| 里程计接收/时间戳年龄 | ≤0.2s / 0.4s；时间配对最大间隔0.08s |
| 里程计断档/姿态跳变 | 开启新积分段，等待断档后真实定位锚点，不跨未知运动外推 |
| 定位纠偏跳变 | 超过0.15m或0.17rad锁定故障，需要重置定位链路；不缓慢掩盖重定位跳变 |
| 定位状态/激光 | tracking、reloc_ok与新鲜点云继续独立检查，预测不能替代障碍观测 |
| 不确定性 | 输出位姿协方差随锚点年龄及创新量增加；诊断标记ODOMETRY_PREDICTED并保留原始年龄 |

因此5s不是允许任意速度盲走5s。低速短时定位迟滞在测量反馈、位移和转角预算内衔接；位移仍限0.12m、转角仍限0.20rad，超预算仍停车。速度反馈/航向的物理精度尚需实机核验，合成测试不替代标定。甲方LO的250ms参考轨迹等待逻辑未被修改，预测是下游连续性补偿。

路线使用有效预测控制位姿维持连续跟踪，同时保留原始定位供记录与诊断。恢复前要求链路有效稳定时间≥1.2s且≥4次控制位姿更新；不足0.3s的暂时不可用不清空累计稳定时间，但不可用时间不计入稳定时长；新预测桥未启用时沿用原始定位检查。失效时禁用执行器，2s内确认停驶，再等最多30s恢复稳定，重新检查/规划同站；超时保留站点暂停。手动接管、急停或用户取消不自动恢复。

## MOLA扫描释放与同步等待

甲方主机等待当前 `scan_ref` 最多250ms，而MOLA默认允许扫描等IMU覆盖500ms。扫描在主机超时之后才释放时，LO后台仍计算，但该扫描结果无法被本次同步调用采纳，主机继续发布数值不变、时间戳前进的保留位姿。图上tracking在线不代表位置真正更新。

建图与定位launch通过 `mola_pipeline.py` 将供应商原始pipeline与项目 `config/mola_localization_overrides.yaml` 合成到运行目录，不修改供应商安装，也不复制一整份配置进入源码。覆盖IMU等待为50ms、待释放扫描最多2帧，给250ms主机预算留出配准时间。IMU覆盖正常时继续融合；迟到时由MOLA降级当前扫描，后续数据正常便恢复。两种甲方模式共用此等待覆盖。该修复没有修改主机硬编码的250ms，极端处理超时仍可能出现。

`held_pose.py`仍拒绝运动中重复的保留位姿，不能靠重新盖时间戳恢复新鲜度。新的真实定位使用原始采集时刻配对里程计并平滑纠偏。恢复门限是停车后的检查，不能将其30s等待时长理解为运动预测许可。

## 执行、到达和控制权

执行器先 `enabled=false` 初始化，最多20s等待本任务DISABLED反馈；链路稳定并核对目标后显式启用。初始化等待与运行中2s停驶确认分开，避免构造订阅时被提前SIGINT。

平移进入8cm到点区即停车，10cm退出滞回，保持零速至少0.5s。预测桥启用时，**还必须收到停车开始之后的真实定位**，确认目标在10cm内才报告ARRIVED；旋转同样要求真实yaw在1.5°内确认。预测能用于提前停车，不能单独宣称成功。任务ID、当前目标、实测位置/朝向和站点上下文共同校验，旧到达结果、SESSION_COMPLETE或进程退出不算到达。

始终保留手动优先、急停、停车锁存、执行反馈超时、原生IK、轮速/舵速、±90°及路径有效期门控。发现手动源立即让出自动输出，清理也不抢发零速干扰手动控制。显式行程/时长测试限额存在时仍有效；一般任务不再因固定0.2m上限提前结束。

## 导航 RViz 环境表面

导航默认显示观测体素的外表面三角网格和地面投影轮廓，隐藏原始点云与膨胀点云。蓝灰为历史/累积地图参考，青绿为当前局部占据表面，金色为统一执行路径；RobotModel 和碰撞包络保留。地面网格沿本次导航拟合平面，不能假定 map 的 z=0 是地面。

显示节点 n01_environment_display 随导航启动，仅发布 Marker/诊断；不修改地图、碰撞、路径或执行器。参考表面最多1Hz，局部表面最多2Hz，默认显示半径12m、地面以上6cm至2.2m。显示体素初始12cm，面数超过24000时自适应放粗，上限30cm；超出预算则报告错误，不悄悄截掉部分地图。表面只包围有回波的体素，不把桌底空隙或没观测到的背面补成实体。轮廓是障碍点的地面投影，不是精准接地外形。

实时层同时检查局部地图消息和桥接扫描时间，超过1s即清除，Marker另有1.5s寿命。历史参考明确用另一种颜色并保留给晚打开的RViz。没有显示订阅者时不重建网格，也不订阅/触发局部占据云导出。可在Displays勾选三个“调试”点云层核对原始观测与规划膨胀；显示模型精细程度不改变导航膨胀或R2模型。

更新后需重启导航以加载显示节点，关闭旧导航RViz后从GUI“导航RViz”重新打开。GUI与launch使用同一配置 src/n01_live_navigation/rviz/n01_live_navigation.rviz；rviz/n01_full_pipeline.rviz 保持相同内容，供手动打开。

## CBF和性能

SCAN负责几何改路。可选CBF是沿名义平移方向的标量速度QP投影，结合实时障碍点和动态轨迹压低速度或停车，不提高名义速度。它不是已标定的全自由度动力学MPC。关闭CBF仍会因定位、路径或底盘约束停车。动态障碍专项实机验收尚未完成。

性能优化包括Release构建、A*同碰撞层可见性重采样、min-snap矩阵求逆复用、原生批量轮组计算、近期有效前缀复核、静态膨胀合并及按需导出可视化。不同地图/模型的基准不能混为实时性能保证，具体样本见 [验证文档](validation.md)。不能未经共享状态同步设计直接把SCAN单线程地图/规划回调改成并发写入。


## 甲方实时建图导航（R2）

总控只选择“方法＝甲方 SLAM3D Lite / 自部署 FAST-LIO2”和“地图模式＝实时 / 离线”。这里离线指已保存PCD，仍使用当前传感器，不是bag回放。

| 地图模式 | 操作流程 |
| --- | --- |
| 离线地图 | ① 启动建图并结束保存PCD（已有地图可跳过）→ ② 启动定位、加载地图并进入跟踪 → 手动启动导航 → 规划后手动启动行驶 |
| 实时地图 | ① 启动实时SLAM（同时建图与估计位姿）→ 等待数据就绪、同步地面 → 手动启动导航 → 规划后手动启动行驶 |

实时模式没有独立定位任务，隐藏PCD加载、重定位和初始位姿控件。导航与行驶不会随着SLAM自动启动；实时SLAM沿用建图录bag、结束保存地图的行为。两个选择运行中锁定，停止后可切换。

以甲方链路为例：选择“甲方 SLAM3D Lite / 实时”，点击“启动实时SLAM”，等待位姿、逐帧点云和底盘里程计就绪。点击“同步地面”，再手动“启动导航”，打开建图/导航 RViz，在已观测区域选择目标并规划，确认路径后再启动行驶。GUI 本身不自动启动SLAM、导航、底盘或雷达。

这个流程不加载旧 PCD，不做旧地图初始位姿匹配，也不需要点击进入 tracking。建图算法仍持续估计机器人在本次 map 坐标系中的位姿；它不是无位姿导航。建图状态只有 session，没有可用的配准质量字段，适配器明确输出 mapping_session_and_fresh_pose，不伪造 map_loaded、reloc_ok 或 fitness。该就绪状态只证明会话活跃和位姿新鲜，不能代表已验证定位精度；扫描配对、里程计预测预算、执行器和手动优先检查继续生效。

| 点云 | 通道与用途 |
| --- | --- |
| 当前逐帧点云 | /livox/lidar/geo_filtered → 导航桥按采集时间配对位姿 → /cloud 与同时间戳 /sensor_pose → SCAN 局部占据/射线清除；用于近期避障 |
| 多帧配准累积点云 | 甲方 /cloud_map → 保留原帧/时间的参考中继 → /grid_map/static_occupancy；全局 A* 参考及 GUI 地面拟合 |

实时参考按甲方地图快照更新，接收端拒绝错误坐标帧、过期/不递增时间戳和超限/损坏消息；SCAN 允许新快照替换参考，离线模式仍只接收第一张静态 PCD。累积图不作为当前扫描进行射线清除。局部窗口内参考是代价，实时观测形成硬障碍；远处仍依赖累积图，搬走的障碍须重新观测，累积点云本身不能保证清除旧物体。未探索区域不是已验证通道。

命令行同一入口：先 scripts/runtime/start_localization_stack.sh slam_mode:=mapping；确认地面后，给 scripts/n01_navigation.sh start 设置 N01_NAV_MAP_MODE=realtime、N01_NAV_REALTIME_REFERENCE_TOPIC=/cloud_map、N01_NAV_GROUND_Z/A/B（当前 map 下拟合的平面系数）。这些命令启动感知/规划，不会自动启动车轮。桌面底盘、雷达和 RSP 仍独立管理。

结束建图先停止执行器和导航，再保存 PCD、结束 bag、停止本 GUI 建图进程。建图重启会建立新坐标系，不能直接沿用旧会话路线；目前持久路线仍要求保存 PCD 并进入该地图定位后记录/回放。实时建图导航的实机避障、到点和长时稳定性需现场验收，离线及隔离测试不代表验收完成。

## 自部署FAST-LIO2后端

项目引入并适配FAST-LIO2，支持离线地图定位与实时建图导航，不直接用其私有位姿驱动底盘。外部源码按 `n01_fast_lio2.repos` 和导入脚本固定版本：FAST_LIO `cc3c9e8b1469b33b8072764d6db2348ed6dc597f`，ikd-Tree `e2e3f4e9d3b95a9e66b1ba83dc98d4a05ed8a3c4`。导入/构建与运行入口由 `scripts/n01 fast-lio-*` 管理，源码和第三方依赖保持独立，不把生成结果混入主工程说明。

FAST-LIO2读取原始 `/livox/lidar`、`/livox/imu`，输出隔离在 `/n01/fast_lio/`，私有map/TF经项目适配器转为规范机身帧。甲方后端读取经过预处理的云；两者使用同一机身/地面语义，不能对FAST-LIO2再次应用甲方预处理倾角。上游固定版本是可重现构建信息，不代表原厂版本已完成本站完整路线验收。


## 实时建图输入与启动时序（2026-11-14）

甲方实时建图先等待新鲜点云及稳定IMU窗口，再建立地图坐标系；30秒未满足则退出，不用缺失输入初始化地图。建图注册输入经 `/n01/slam/mapping_scan` 按目标5Hz固定采集时间节拍限频，保留原采集时间戳和点字段；导航仍直接使用全频 `/livox/lidar/geo_filtered`。

低速建图配置与现有低速定位一致，采用LiDAR线性去畸变，保留IMU互补滤波和倾角预处理；暂不采用已观测到同步扫描释放断档的后端IMU融合。此选择尚无高速或动态实机精度验收。减小ICP采样数量的实验没有消除断档，未保留1200/5000点配置。

实时会话状态分别报告原始位姿是否新鲜和是否仍在有效预测范围。旧位姿仍保留原时间戳；预测继续受里程计新鲜度、5秒、0.12米及0.20弧度上限约束，不能通过重复保留位姿刷新有效期。


## R2航向预测（2026-11-14移动数据修复）

导航本地里程计将平移速度和Z轴角速度分别按真实消息时间戳做梯形积分。航向不再逐帧直接采用底盘 `/odom.pose` 的yaw；该yaw在一次移动记录中有与定位及自身角速度不一致的跳动。初始yaw、真实时间断档后的yaw仍取原姿态；roll/pitch保留原值。这是R2平面移动预测，未修改底盘消息或底盘控制参数，不适用于据此宣称高动态三维姿态精度。

超过80ms的里程计时间断档仍建立新段并等待本段真实定位；角速度缺失、非有限或超预算拒绝。原有预测距离、转角、时间和纠偏跳变保护不放宽。纠偏跳变已锁定的旧进程不会被代码热更新自动清锁，停车后手动重启定位/建图链加载新实现；诊断优先显示锁定原因，不再误报成单纯位姿过期。


## 项目通信与建图采样节拍

项目GUI、甲方建图/定位和导航的脚本入口共用 `scripts/lib/ros_transport.sh`。`N01_RUNTIME_RMW=auto` 默认在私有运行依赖可用时选择CycloneDDS，缺失时明确警告并保留原通信实现；`N01_RUNTIME_RMW=rmw_fastrtps_cpp` 可显式回退。依赖目录默认 `n01_runtime/deps/cyclonedds/root/opt/ros/humble`，可用 `N01_CYCLONE_PREFIX` 指定。此设置仅作用于项目进程树，不会重启或修改桌面底盘、遥控、雷达/RSP入口；已有进程须停车后由GUI重新启动链路才加载。

采样器按采集时间固定节拍、容忍最多2ms抖动，补过已错失的时槽而不排队补发，保留原始点云及采集时间。之前逐次用“距上次转发至少200ms”判断，遇到199.xms就额外跳帧；新版测试10Hz加1ms抖动的输入仍转发约5Hz。突发丢帧后短期相邻输出可能相隔100ms，长期按5Hz节拍，不保证每对输出严格相隔200ms。每10秒日志报告接收/转发计数，可定位注册输入不足，而不是凭观察者单独收到的帧数推断发布频率。


## 感知通信与底盘控制通信分开配置

点云感知链可使用私有CycloneDDS以改善大消息接收。执行器、无地图短程工具、底盘模型参数读取及轨迹可行性监视仍采用FastDDS：当前Humble Cyclone环境的跨进程MessageInfo发布者标识与图端点标识不匹配，不能用既有GID比较来可靠排除自身命令。隔离私有话题实测100次自身零速消息，Cyclone监视器均报unknown；FastDDS仅报告READY，无误报。参见[ROS 2问题377](https://github.com/ros2/rmw_cyclonedds/issues/377)。不得以忽略未知来源或零速命令绕开手动优先。

控制入口在导入期间已加载错误RMW时，会在ROS初始化前以相同Python启动参数重新执行并选择FastDDS；若ROS上下文已运行则拒绝切换。启动脚本也在Python启动前显式选择控制RMW。该处理不改变运行中底盘的任何参数。

纯控制工具增加forward短程模式，上限0.1m、默认不执行、沿初始朝向移动并检查横向/航向漂移；命令积分预算同时包含两个平移分量。该工具仍用原始轮式里程计判断位置，不作为真实物理距离标定仪器。


## RViz物体轮廓显示

环境显示默认采用实测回波上的局部定向面片，而非占据体素立方体：以真实回波作面片中心，邻域PCA估计切平面，每个小面片独立，不跨越未观测空隙连接，不投影出方格地面外轮廓。参考地图和实时层仍分色；规划膨胀体保持单独调试开关。显示不会新增碰撞占据或改变规划地面过滤。

面片目标采样6cm、每层最多4000片，面片半径最大6.5cm；预算不足时稀疏采样，避免把物体扩成大方块。该显示保留已有回波形状，不做语义识别或凭空补全椅腿；已保存地图若本身20cm降采样，无法从它恢复细轮廓。重启导航显示节点及RViz加载新效果。

实时面片输入使用运动补偿实测 `/cloud`，不使用规划 `/grid_map/occupancy` 的栅格中心，避免轮廓在输入阶段已方块化。环境显示节点随导航启动/停止；仅打开导航RViz不会启动导航或显示节点，导航停止时该配置的曲面层没有发布者。可在仅建图时打开建图RViz查看地图。


## 前进转弯局部规划、状态与旋转检查（2026-11-14）

GUI导航采用 `reduced_v_omega_curvature`、`face_path=true`：非负vx、vy=0，机头随路径转弯。记录路线同样采用此策略；纯控制lateral工具仅供明确独立测试。全局SCAN A*提供参考路线，SCAN B样条提供局部引导；轨迹监视器增加前进SE(2)格点搜索，从新鲜机身朝向和 `/odom.twist` 曲率出发重新生成可执行局部段，不再直接把无朝向约束的B样条送给跟踪器。

搜索控制量为曲率，范围±1/m（最小移动转弯半径1m）；曲率沿弧长渐变，最大2/m²，避免每段转向突跳。运动基元通常长20cm、每2cm检查碰撞；局部目标取引导路径前方最多2m，目标位置容差6cm，不强行连直线或把末点吸附到目标。中段交接还约束终端朝向。每次最多120ms、2500次展开；失败不发布半条可执行路径，明确报告起点包络占用、时间预算、展开预算或无前进路径。它是局部有界搜索，不是任意场景可达性的证明，狭窄处可能仍需停车旋转。

碰撞输入为有效 `/grid_map/occupancy`，沿用地图与当前观测融合策略；在滑动窗口外拒绝搜索。该层不提供完整未知空间标记，不能据此宣称未观测空间安全或具备悬崖检测。输入占用层、机身位姿、里程计、地面参数必须有效且新鲜，缺失不放行。地面过滤为3cm，低矮物体仍取决于实际雷达回波及预处理。

水平机身覆盖仍为三个圆的并集：半径0.33m，圆心x=-0.43/-0.10/+0.23m。新搜索逐姿态旋转该包络，不复用固定朝向的膨胀图；额外仅覆盖5cm体素的半对角线和2cm离散采样间隙，不叠加0.80m整圆。原地旋转使用相同包络，按当前位置到目标朝向的最短角度每不超过2°检查扫掠范围，同时检查新鲜全周雷达和有效占用层。原0.80m整圆函数保留用于旧诊断，不再作为旋转任务的实际拒绝条件。未缩小物理机身包络，未修改桌面URDF或控制器参数。

URDF轮半径0.095m、安装间距0.56/0.27m、轮偏移0.085m与控制器配置一致，但旧URDF转向limit仍为±90°，运行限制按实时底盘参数读取（用户已确认±180°）。搜索路径仍须通过原生Hive2四轮IK、实测轮角、轮速及转向速率审核；纯速率超限最多4次降速复核，审核速度随反馈传给执行器。轨迹与审核以candidate_stamp_ns绑定，禁止新路径借用旧审核。统一路径保留原目标，未审核后缀不能执行。

状态包括等待就绪、跟踪、停车转向、重规划、到达确认、成功、失败及手动接管。优先跟踪新鲜审核通过的前进曲线，避免仅因全局切线偏转就强制停车旋转。没有可执行前进路径且全局朝向误差超过35°时，停车并用新鲜底盘速度确认连续0.3秒停稳后检查原地转向；对齐后等待新局部路径。旋转完成不等同于站点到达。旋转受阻进入有限恢复：经正常Goal Gate重规划原目标，间隔8秒、最多3次、窗口30秒，仍无可执行路径则RECOVERY_FAILED结束，不自动倒车或横移。

GUI启动及任务最终结果提示5秒自动关闭；中途运动状态仅记日志。此版本通过离线搜索、碰撞、原生IK与接口回归，尚未完成当前现场实机验收。停止旧任务后重启导航及执行器加载，不会自动恢复之前失败任务。


### 短时差异恢复与搜索连续性

旋转校验改为按真实 `/odom` 消息时间戳积分实测angular.z，与本任务地图航向变化比较，不再用已发现跳变的原始 `/odom.pose` 航向。积分时间断档超过80ms建立新段，正在旋转的任务拒绝跨段继续积分；不伪造缺失角度。地图位姿预测也使用实测角速度，所以这不是两个完全独立的航向真值，最终转向到达仍需停车后的真实SLAM测量确认。

旋转航向不一致、输入过期、底盘运动学拒绝或未停稳持续2秒后，退出旧旋转状态，进入既有30秒有限恢复；异常恢复还要求后续真实定位确认当前位姿。不会通过清零旧差异立即恢复旋转，也不会自动重新启用已失败任务。ROTATION_TIMEOUT、ROTATION_DRIFT现为GUI最终失败事件，只报告一次，避免显示成永远等待。

局部搜索一次批量检查五个后继运动基元，KD查询限定碰撞半径。同一目标的上一条曲线最多保留2秒，不因复用续期；每次用新鲜占用层检查完整剩余曲线，偏离原曲线超过2cm、航向超过2°、曲率差超过0.15/m或目标变化均不复用。偏移距离额外加入碰撞检查半径。默认约0.8秒尝试新搜索；超时可继续重新验证过的剩余曲线，但仍须通过新鲜反馈和原生四轮IK审核。无有效曲线、感知过期或新障碍侵入时仍停车。B样条窗口有效时，短时失败仍继续重试审核，不因失败清空显示后就停止重试。

底盘参数GetParameters请求超过1.5秒未回复会清理旧请求并重试；仍要求最近3秒内有效参数，不能用默认参数绕开失联。


### 全局定位短时中断的统一策略

定位桥、健康监督、候选审核、GUI路线及执行器区分“原始全局观测”与“当前控制估计”。原始全局观测可短时过期，由连续实测里程计推进当前控制估计；不修改原始观测时间戳。桥发布tracking_mode，执行状态发布tracking_continuity；预测跟踪日志明确标注等待全局定位修正。控制估计统一要求采集年龄不超过0.4秒、接收间隔不超过0.5秒，这些要求针对持续推算的控制估计，不要求每0.4秒收到全局SLAM定位。

预测依旧最多5秒、相对锚点位移12cm、转角0.20rad，先达到哪项就停止。全局观测年龄超过0.7秒或原始接收已过期时，平移执行速度限制0.03m/s，所以几秒定位间断可以覆盖，但不保证任意方向/速度都能运行满5秒。最新有效定位状态的消息沉默允许在同一预测窗口内保持；明确失败状态立即生效。里程计时间断档、雷达失效、超预算或纠偏跳变故障仍停止；恢复后的正常小修正沿用平滑纠偏，最终位置和朝向仍由真实测量确认。

GUI路线在桥已经确认可用控制估计时，不再重复要求原始pose/loc_status接收间隔新鲜；地图绑定、明确失效会话和用户接管仍有效。保存示教点等需要记录实测状态的操作不因此放宽。


### 局部路径交接容错

候选路径与审核消息采用32版本、0.6秒窗口配对缓存。新版本只到达其中一个话题时，仍可使用有效期内上一对完整版本；最新审核明确失败时不靠旧缓存绕过。统一路径状态附带execution_review，与自身path_stamp_ns及candidate_stamp_ns一起绑定，执行器使用这份审核及速度限制，避免拿最新独立审核去否决正在执行的另一版本。

局部前段与全局后缀的间隙/方向差只影响尚未执行的参考后缀，不再否决经过审核的局部前段。suffix_requires_local_replanning标明后续必须局部重规划；validated_prefix_points仍是唯一可执行范围，前段耗尽仍等待新验证路径，不把接头连线放行给执行器。严格splice_path检查保留供其他调用，导航使用reference_tail_only模式。


### 点选目标的停车转向接入

全局路线已生成但前进曲线搜索超时/展开耗尽/未找到前进路线时，若目标与当前朝向相差超过35°，GUI可进入“等待先对齐朝向”，不再要求先有平移局部路径。必须具备新鲜控制位姿、审核反馈以及终点匹配本次目标的新鲜全局路线；明确起点占用、感知过期等错误不走此入口。点击行驶才执行原有实际扫掠检查旋转，真实定位确认转向完成后重新发布同一目标，获得新的有效局部路径后创建平移执行器。转向中的目标更改会中止旧动作，旋转受阻也不会放行平移。

1/m曲率上限是前进转弯跟踪策略，不是URDF或底盘的机械最小半径；原地转向独立处理。等待超时报告“尚未找到可执行曲线”，不声称已经证明无路。相同起点和目标的失败搜索间隔至少0.4秒，起点/朝向/目标明显变化后立即重新尝试，避免每次回调都耗尽120ms预算。


### 当前膨胀配置（10点审计后）

基础三圆半径现为0.30m（替代0.33m），与launch中的环境膨胀半径一致；局部审核再含5cm体素半对角线和2cm采样余量，总查询半径约0.355m。当前姿态URDF投影所需覆盖半径约0.228m，0.25m只剩约2cm基础余量，本次未采用该更小值。此核对不是全关节活动范围认证。紫色包络数据在搜索失败/等待时也发布，以显示当前计算配置，不代表该路径审核已通过。新Goal Gate目标清除旧候选B样条、重验证缓存，避免旧目标搜索占用CPU。


### 环境6cm与机器人覆盖分离（当前定义）

`grid_map.environment_margin=0.06` 是环境障碍的名义外扩距离；`grid_map.double_cylinder_radius=0.30` 保留机器人基础三圆覆盖，两者不是同一个参数。全局A*和SCAN内部中心禁入区使用两者之和0.36m；局部前进/旋转检查对原始占用查询同一0.36m，原5cm体素半对角线+2cm采样余量合计约5.54cm，包含于6cm预算，不再另叠加。路径复用位置偏差仍作为单独不确定性增加到机器人侧包络。

新增 `/grid_map/environment_inflate`：由同一实时占用及environment_margin生成机身碰撞高度带的二维投影，仅含环境外扩，不含机身尺寸；复用原始占用导出，不再扫描第二份三维体积。GUI琥珀色改订阅此层，紫色显示基础机器人近似覆盖及复用不确定性。旧 `/grid_map/occupancy_inflate` 保留供内部/调试使用，含机器人覆盖的中心禁入区，不能标作物体外扩距离。状态分别报告environment_margin_m、robot_footprint_radius_m、collision_query_radius_m。

当前5cm栅格只能离散表达6cm圆，不能把名义6cm余量宣称为6cm定位/感知精度。环境层不因为显示变小而把机器人当成点，内部完整碰撞覆盖仍有效。GUI与导航需重启加载新的话题和计算参数。
