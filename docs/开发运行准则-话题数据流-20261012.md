## 3. TF 树现状与约束(2026-10-12 实测)

现场 `/tf` + `/tf_static` 全量:
- 静态:`base_footprint→base_link→lidar_link / lpms_imu_link`,以及 legs→foot 链。
- 动态:`base_link→fl/fr/rl/rr_hip→thigh→foot`(腿关节),无 odom/map 边。
- **缺**:`odom→base_link`、`map→base_link`、`livox_frame→base_link`。

local_map `updateTF()` 查 `map→lidar_frame`,失败会**卡在 "wait for lidar"**。M1 下:
- `pose_topic:=/odom nav_frame:=odom pose_child_frame:=base_footprint`(odom→base_footprint 由 pose_tf_bridge 转发 /odom 补;
  **严禁挂 base_link**:甲方 RSP 静态 `base_footprint→base_link` 已在 /tf_static,再发 odom→base_link 会双 parent 分裂 TF 树,
  审计 2026-10-13 确认为 M1 断链必现根因)。
- **点云 frame 与 `lidar_frame` 必须真正对应**:甲方原始点云 frame=`livox_frame`,甲方静态 TF 有
  `base_link→lidar_link`(平移 0.295/0/0)但**无 `livox_frame` 边**。
  - `lidar_frame:=livox_frame` → 查 `map→livox_frame` 失败、兜底 `base_link→livox_frame` 也失败 → 卡 wait for lidar;
  - 保持 `lidar_frame:=lidar_link` → 甲方有 `base_link→lidar_link` 可兜底转出,但实际点云 frame 是
    `livox_frame`,名称不配,pcl 会用 lidar_link 的变换去转 livox_frame 的点 → 方位偏差。
  - **根治 = 甲方发布 `livox_frame→base_link`(雷达外参)静态 TF,此属甲方,乙方不代做。**

## 4. 启动前置 checklist(乙方 launch 前必须逐条物理满足)

1. `ros2 topic list | grep livox` → 必须含 `/livox/lidar`(无 SLAM 也可)。
2. 若要用 `/livox/lidar/geo_filtered`:必须 `ros2 topic list` 有该话题 + `enable_forward: true`;否则改订 `/livox/lidar`。
3. `/odom` 必须有发布者(`chassis_controller`)。
4. M1 / 真机模式都必须有 `odom→base_link`(M1 由 pose_tf_bridge 补;真机由甲方或 bridge)且 `map→base_link`(真机必需,由甲方 SLAM GUI 定位)。
5. 雷达 frame:确认与 `lidar_frame` 参数一致;不匹配会卡 `wait for lidar`。

## 5. 乙方数据来源铁律（每次写代码/launch/默认值前必读，2026-10-13 用户强约束）

乙方导航依赖的**每一个可用于运行的数据**（frame、TF 边、话题、消息字段）只能来自：

1. **甲方实际发布的**（已在现场或甲方文档确认有节点在发）；或
2. **用户人工测量** [参数文本.txt](/home/demo/lyy/docs/参数文本.txt)（第 8/9 节真实静态外参已与甲方 URDF 源码交叉验证，可作为固定参数）。

**乙方不得凭空产生/臆造 frame、TF 边、话题或数值。**

用某个 frame/TF/话题前，必须先回答（写进代码/默认值/launch 之前）：

- **它是否存在**：`ros2 topic list` / `ros2 run tf2_ros tf2_echo` 看得到吗？谁发布？哪个进程？
- **它是否需要前置条件**：是运动栈即起，还是要 SLAM 栈、或 **GUI 操作**（进入 tracking/localization）才会发布？
- **数据流是否真的到达乙方**：前置已满足时，这个子/话题确实在发，乙方订阅后才有数据；前置未满足时，"乙方代码里没提提醒用户、用户没做 GUI、话题不存在" → 乙方空数据/无输出。

**GUI 前置话题的硬规则**：代码里一旦用了（如 `/robot_pose`、`/localization_status`、`/livox/lidar/geo_filtered`），
必须在 launch 注释 / 启动日志 / 运行脚本前置检查里**显式提醒用户**该话题需要 GUI 操作才会发布；不能只写进代码而让用户无从知晓前置，否则视为违规。

> 反例（禁止）：乙方写死 `/robot_pose`，用户没开 SLAM 栈 + GUI，话题不存在 → 空数据。
> 正例（要求）：乙方用了它，必须在 launch 里写明"需要甲方 GUI 进入定位"并要求前置检查。
