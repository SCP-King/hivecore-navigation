# HiveCore GUI-SLAM 精简问题报告

**问题编号：** HC-INT-002
**涉及模块：** HiveCore GUI-SLAM（hivecore_slam3d / mola / MRPT，lyy 分支）
**当前状态：** 已复现，待甲方定位修复

## 一、问题清单

### ① slam3d_node 段错误（SIGSEGV，exit -11）

- **现象：** start_mapping 后首个扫描处理周期（初始重定位完成后）崩溃；2000ms warm-up guard 期满后仍触发；IMU 缺失为伴随警告，非根因。
- **证据：** 本次复现运行日志（`/home/demo/lyy/slam_workflow/run/logs/`）含 `process has died, exit code -11`，二进制来自 lyy 树 `install/hivecore_slam3d`；guard 文案点名 "avoids first-scan KeyframePointCloudMap SEGV"。
- **甲方动作：** 取 coredump / gdb 回溯定位具体崩溃行。段错误已发生为确定结论，具体代码位置未取证，不以相邻日志推断。

### ② lyy 树默认配置仍处已知崩溃路径，且文档与实际不符

- **现象：** lyy 树默认局部地图类 `mola::KeyframePointCloudMap`（启动/工作流无 `MOLA_LOCALMAP_CLASS` 覆盖）；FROZEN 同文件默认 `IncrementalPointCloud`，注释明文记载该图类在 MRPT 2.15 + MOLA 3.2 下首个实时扫描 SIGSEGV。lyy 配置 `album_pin=pin_imu`，无 `enable_imu_fusion` 键；FROZEN 为 `deskew_pin` + 显式 `enable_imu_fusion: false`。
- **文档矛盾：** README_cn.md 声称默认 "KISS-ICP + IMU 关 + PGO"，实际配置为 mola + IMU 去畸变已启用，仅 PGO 相符。
- **甲方动作：** 切换默认图类到 `IncrementalPointCloud` 并对齐 FROZEN 已验证配置（`deskew_pin` + `enable_imu_fusion: false`），或从 ABI / core 库层面根治；文档与实际配置自查一致。

### ③ MRPT 系统环境已干净闭环；显式触发仍为残余风险

- **现象：** 系统侧已恢复干净：`ros-humble-mrpt-lib*` 均为 2.15.21 且显式 hold，`dpkg --audit` 无输出，`/opt/ros/humble/lib` 无 3.5 soname，系统级 `libmrpt_libros_bridge` 已移除。
- **现存风险：** lyy 树 `robot_apt.sh` 安装清单仍含 `ros-humble-mrpt-libros-bridge`（4.x 会拉入 MRPT 3.5 链），显式重跑可能重现 ABI 混合 / exit127；FROZEN 脚本已显式屏蔽该包。
- **甲方动作：** 验收前勿在 lyy 树执行 `robot_apt.sh`；被动 apt 升级受 hold 保护，无需其他操作。

### 其他观察

- `octomap_server_node` 也曾 exit -11，属另一独立重启周期事件，非同一崩溃，单独观察即可。
- 传感器自动建图触发问题（乙方 sensor_gate 工作流）已由乙方修复，非甲方问题主体。
