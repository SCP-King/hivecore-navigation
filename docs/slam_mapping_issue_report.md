# SLAM 建图自车点残留问题报告（给 SLAM 工程师）

## 1. 现象

建图保存的 PCD 中，沿机器人历史行驶轨迹存在车体/腿/轮形状的点。导航把 PCD 当静态先验后，这些点会变成静态障碍，表现为：

- 起点机身包络被“自己”挡住；
- 路径中间出现车体形状的障碍带；
- 窄通道/拐角处更明显。

## 4. 初步判断

ego box 是启用的，**不是被关闭**。残留更可能来自：

1. **腿/轮低于 z=−0.3**，不在过滤盒内；
2. x/y 超出 ±0.5 的支架/负载；
3. 过滤盒基于 `base_link`，实际车体/腿的外形覆盖不足；
4. 建图早期/参数切换前的历史点；
5. `/cloud_map` 累积时没有按历史轨迹二次过滤。

## 5. 建议 SLAM 侧评估

1. 用实际 URDF/机器人外形复核 `filter_box`：
   - z 下限是否应从 −0.3 扩到 −0.8；
   - x/y 是否覆盖腿、轮、雷达支架。
2. 在 `/cloud_map` 累积/保存前增加**历史自车位姿过滤**：
   - 用建图轨迹 + 机器人足迹；
   - 或保证 ego box 覆盖全车。
3. 输出过滤统计：
   - 每帧过滤点数；
   - 累计自车点；
   - 保存 PCD 时报告。
4. 建议随 PCD 保存一份建图轨迹（`/robot_pose`），便于离线复核/清理。
5. 如果短期不改建图端，请确认导航侧按轨迹清理 PCD 是允许的交付方式。

## 6. 验收方法

1. 静态场景建图，机器人走一圈；
2. 保存 PCD；
3. 用轨迹 + 足迹清理，统计删除点数；
4. 清理前后对比：
   - 删除点应主要落在机器人历史轨迹附近；
   - 墙体、桌腿、真实障碍应保留；
5. 导航起点不再因历史自车点 `start_occupied`。

## 7. 备注

- 本次删除比例 0.75%，但导航对起点/窄通道很敏感，少量残留也会造成失败；
- 地图高处点占 23%（z>1.2），导航静态源已限定 z −1.2~1.2，不直接影响本问题；
- 真实障碍若曾进入机器人足迹，清理时也会被删，这是“机器人已经在那里”的代价，需要在验收中说明。
