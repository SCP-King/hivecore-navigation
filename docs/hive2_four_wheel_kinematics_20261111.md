## 1. 实际机构和证据

这是四轮独立转向、独立驱动的 4WIS / Swerve 底盘。四个 ankle_yaw 控制
轮组方向，四个 wheel 关节控制滚动。理想平面底盘速度有 vx、vy、ω 三个自由度。
侧移需要舵轮先转到相应方向，因此不能把它当作可瞬时改变速度方向的质点。

直接读取本机安装版本 `/opt/hivecore/hive2-motion/1.0.0/install/`：

## 2. 坐标与状态

车体系 B：x 向前、y 向左、z 向上；ω 逆时针为正。
平面位姿 q=(X,Y,ψ)，车体速度 ξ=(vx,vy,ω)。

```
X_dot = cosψ vx - sinψ vy
Y_dot = sinψ vx + cosψ vy
ψ_dot = ω
```

每轮状态包括实际舵角 θ_i、舵角速度 θdot_i、驱动角速度 φdot_i。
后续控制模型还应包含底盘和舵轮 OTG 的参考状态，不能只保留 q。

## 3. 一般接触几何与刚体约束

令真实舵轴投影为 a_i=(a_x,a_y)，舵轮零位下从舵轴到轮心的水平偏置为 b_i。
这是通用形式，避免把 hip 安装点、舵轴、轮接地点混为一个点。

```
J = [[0,-1],[1,0]]
c_i = a_i + Rot(θ_i) b_i
t_i = (cosθ_i, sinθ_i)            # 当前安装的滚动方向
n_i = (-sinθ_i, cosθ_i)
u_i = (vx,vy) + ω J c_i + θdot_i J Rot(θ_i)b_i
```

假定平地、轮轴水平、轮不离地、不打滑，则必须同时满足：

```
t_i · u_i = R φdot_i             # 沿轮面滚动
n_i · u_i = 0                    # 横向不滑移
```

对本机左右向外偏置，定义 s=(+1,-1,+1,-1)，b_i=(0,s_i d)：

```
c_x = a_x - s_i d sinθ_i
c_y = a_y + s_i d cosθ_i
R φdot_i = cosθ_i vx + sinθ_i vy
           + (-c_y cosθ_i + c_x sinθ_i)ω - s_i d θdot_i
0 = -sinθ_i vx + cosθ_i vy
    + (c_y sinθ_i + c_x cosθ_i)ω
```

转舵补偿因此为 **-s_i d θdot_i/R**，与甲方 roadmap:431 的符号一致。
舵速 1 rad/s 时，补偿幅度约 0.8947 rad/s；而直行 0.03 m/s 的轮速只有
0.3158 rad/s。低速测试里，这个效应比期望驱动轮速还大，不能略去。

## 4. 逆运动学：车速到舵角、轮速

先在舵轴处算刚体速度 w_i=(vx-ωa_y, vy+ωa_x)。稳定舵角满足横向约束，
名义目标为 θ*=atan2(w_y,w_x)。速度近零时保持当前舵角，避免 atan2(0,0) 抖动。
在满足机械限位的候选 θ*+kπ 中，结合当前角、转动代价和回零偏好选择支路。

随后按**实际反馈舵角**计算接地点和投影轮速，并加转舵补偿。
不能把 sqrt(w_x²+w_y²)/R 直接当成最终轮速；它遗漏接地点偏置和转舵运动。
偏置存在时，选择 θ+π 后应重新计算 c_i 和轮速，不能仅把旧轮速变号。
舵角未到位时，期望车速通常不满足所有横向约束，必须经过对齐门控/减速。

甲方安装头文件与 roadmap 表达的执行链为：

```
cmd_vel(vx,vy,ω) → 监督器/超时门控 → 车体三轴 OTG
→ 转向目标及支路优化 → 四舵角 OTG
→ 反馈舵角下的接触点驱动投影 + 转舵补偿
→ 对齐/限幅/电流导纳等门控 → 驱动器
```

具体门控执行顺序仍应以实现核对；文档中的 cos 对齐缩放不能被当作精确速度闭环。

## 5. 正运动学：四轮反馈到车速

每轮贡献两个方程。令 B_i=-c_y cosθ+c_x sinθ，C_i=c_y sinθ+c_x cosθ：

```
[ cosθ   sinθ   B_i ] ξ = R φdot_i + s_i d θdot_i
[-sinθ   cosθ   C_i ] ξ = 0
```

堆叠成 8×3 的 Aξ=b，用带权最小二乘求解，使用 QR/SVD 并检查秩和条件数。
滚动与侧滑约束的权重应反映实际噪声，不能把打滑轮当作无限精确观测。
残差 RMS 可提示滑移、几何错误、舵角未对齐或反馈不同步。
只有轮速反馈真实且时间同步时，正解才有意义；下发速度不等于实际速度。
里程计应对车体速度作 SE(2) 积分，并用实际时间间隔；静止噪声路径长度不能
直接当作净移动距离。当前配置另启用 IMU 航向融合，不代表平移也被外部观测校正。

## 6. 必须先解决的几何和限位不一致

1. 控制器头文件把 ±Lx/2、±Ly/2 标为 pivot。URDF 实际将 hip 放在
   (±0.28,±0.135)，ankle_yaw 又向内偏 0.085 m，再由轮心向外偏回。
   腿竖直且 θ=0 时，URDF 舵轴 y=±0.050，轮心 y=±0.135；若控制器
   将 ±0.135 直接作为舵轴并向外加偏置，则零位轮心 y=±0.220。
   这两种模型相差 85 mm，须用已展开 URDF、控制器实算和实测互证。
   不能在导航模型里擅自选择其中一种来消除差异。
2. URDF ±90° 与控制器软限 ±180° 不一致。物理限位未确认前，不能按
   ±180° 证明轨迹可执行，也不能仅依据注释擅自修改底层限位。
3. Hive2 两段腿各 0.38 m；腿姿变化会改变实际舵轴位置和轴线方向。
   平面定几何模型只适用于已确认的固定腿姿、近水平地面。腿运动时应由完整
   关节变换重建 a_i、轮轴和接触点，不能套用 Hive3 默认配置。

## 7. 与现有导航的差距

改动前 `four_wheel_steer_screen` 只是必要条件筛查：假设 vy=0、ψ沿路径切向，
采用名义矩形点，未包含 d、转舵补偿、舵角速度/加速度、车体 OTG 和对齐阶段。
折叠舵角后轮速仍取正幅值，也不能作为可直接下发的逆解。上述自写逆解现已替换。
当前 slow_motion_executor 只输出 vx 和 ω，未利用横移自由度；超过航向误差门限
直接输出零速的 ALIGN 分支，也没有完成对齐动作。因此它还不是完整的全向跟踪器。

全向路径应描述 (X(s),Y(s),ψ(s))，车身航向不必等于路径切线：

```
[vx_ref,vy_ref] = Rot(-ψ)[X_dot_ref,Y_dot_ref]
ω_ref = ψ_dot_ref
```

下一步跟踪器与约束应统一使用三轴速度及真实轮状态，限制舵速、轮速和变化率。
CBF 也需要在 (vx,vy,ω) 控制空间、真实外廓和执行延迟下建模；现有只裁剪
前进标量速度的模块仅是初步速度过滤器，不能替代四轮全向可执行性验证。

## 9. 已落地的软件对齐

- `hive2_native.cpp` 仅做 C ABI 转接，直接调用同一
  `/opt/hivecore/hive2-motion/1.0.0/install/lib/libmotion_controller.so`。
  不初始化 ROS、不实例化硬件控制器、不调用驱动服务。
- `hive2_kinematics.py` 提供三轴逆解、反馈正解、接触点表达；安装 YAML
  是几何参数来源。导航声明参数与安装 YAML 冲突时明确拒绝，禁止静默退回近似模型。
  SDK 缺失、轮轴方向不支持、反馈/补偿配置不匹配时也明确失败。
- 原生目标角保留底盘支路优化结果；驱动轮速保留正负号、反馈舵角投影及转舵补偿。
  正解直接复用底盘最小二乘实现，避免两套求解器漂移。
- 路径筛查改用上述原生逆解，增加 20 rad/s 轮速和 1.57 rad/s 舵速检查；
  路径仍按切向航向重新计时，只是必要条件筛查，不声称验证原 B 样条的全部时域动力学。
  初始转向对齐单独报告，未伪造其耗时。
- 执行器订阅现有 `/joint_states` 的四个 ankle_yaw 位置与速度；缺字段、陈旧、
  非有限值都停车。发送速度前使用同一原生逆解检查轮速、舵速与保守舵角界限。
  仍只向底盘发车体 `/cmd_vel`，不越过甲方控制链直接发轮指令。
- 底盘软限保持 ±π；导航额外执行 URDF ±1.5708 保守边界。冲突显式上报，
  没有修改厂商安装文件或通过扩大限位消除告警。
- 控制器几何作为软件计算真源，原“hip 当接地点”的导航近似已删除；URDF 与
  实际接地点是否一致仍待标定。`controller_model_verified` 只表示复用了原生
  几何库，`controller_dynamics_verified`、`wheel_contact_geometry_verified` 保持 false。

离线验证：直行、横移、倒车有符号轮速、原地转向未对齐残差、转舵补偿、支路连续性、
失效拒绝及参数冲突检查。100 组随机状态将原生驱动投影和 8 行 FK 与独立矩阵公式核对。

的断言（launch 中当前 pose age=2.0 / cloud age=1.6，断言仍要求 1.5 / 0.9），
不属于本次运动学改动，未为使测试通过而修改运行时新旧时间阈值。
