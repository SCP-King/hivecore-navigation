## 2. 甲方平台结构：先理解谁负责什么

```text
甲方 Hive2 驱动/运动栈
  ├─ chassis_controller → /odom（现场确认为 odom / base_link）
  ├─ Livox driver → /livox/lidar（PointCloud2，livox_frame）
  ├─ chassis state / SDK / 速度命令等
  └─ robot_state_publisher（其中一条静态 TF：base_footprint→base_link）

甲方 GUI-SLAM：gui_slam_console.launch.py
  ├─ IMU complementary filter
  ├─ robot_state_publisher（目前存在与运动栈冲突的同名静态 TF）
  ├─ static_tf_publisher_node
  ├─ lidar_cloud_preprocess_node → /livox/lidar/geo_filtered（lidar_link）
  ├─ slam3d_node（启动初态：外层 Idle，内层 Stopped）
  └─ slam3d_services_gui（GUI 只是服务客户端，不等于正在定位）

GUI 的建图或定位服务操作
  └─ slam3d_node 切换工作角色/会话
       ├─ Mapping → /cloud_map、建图轨迹与 /mapping_status
       └─ Localization → /robot_pose、map→tracking_frame TF、/localization_status
```

**特别注意**：新版 `gui_slam_console`、`mapping_console`、`localization_console` 属于不同启动模式，说明书明确要求**不要叠加启动**。在 `gui_slam_console` 已运行时，不得为了“激活定位”再起一个 `localization_console`。

## 3. 新版 GUI 状态机：最容易操作错误的部分

### 3.1 外层模式（Outer Role）

- `Idle`：新组合 GUI Console 默认外层模式；建图与定位的内层会话初始均停止。
- `Mapping`：建图角色。内层可为 `Stopped / Live / Frozen / Relocating`。
- `Localization`：定位角色。内层可为 `Stopped / Relocalization / Tracking`。
- **Mapping 和 Localization 外层互斥**，只有两侧内层都停止后，才能经 `Idle` 中转。

新版核心服务由 **`slam3d_node`** 提供（不是旧版 `lidar_3d_localization_node`）：

| 作用 | 新版服务 | 风险 |
|---|---|---|
| 切至 Idle | `/slam3d_node/enter_idle` | 改变工作角色，运行会话时可能拒绝 |
| 切入建图角色 | `/slam3d_node/enter_mapping` | 需先中转 Idle；不是建图会话 Start |
| 切入定位角色 | `/slam3d_node/enter_localization` | 初始化定位组件，可能加载预设 PCD |
| 开始建图 | `/slam3d_node/start_mapping` | 可能重置会话和本地地图 |
| 停止建图 | `/slam3d_node/stop_mapping` | 更改会话，保留/改变数据状态需核对 |
| 开始定位 | `/slam3d_node/start_localization` | **需要已加载定位 PCD**；进入 Relocalization |
| 进入跟踪 | `/slam3d_node/enter_tracking` | 不等于“定位成功”的证明，须先评估质量 |
| 进入重定位 | `/slam3d_node/enter_relocalization` | 重定位/重新配准 |
| 加载地图 | `/slam3d_node/load_map` | 共享服务名，含义取决于当前外层模式 |

**禁止本阶段调用上述服务**；先通过 `ros2 service list` 比对是否真的存在。新手册明确说明新版**未提供** `reload_localization_parameters` 和 `set_relocalization_engine` 服务，即使 GUI YAML 仍保留这些映射，点击相关按钮也可能超时。

### 3.2 七个 GUI 标签页速查

| 页面 | 用途 | 禁止误操作 |
|---|---|---|
| `preprocess` | 点云几何滤波、Cloud forward | Disable 会使下游过滤点云静默；调参会改变点云 |
| `mapping` | 建图 Start/Freeze/Reloc/Resume/Stop、Save/Load | `mapping Load` 是旧图**叠加/先验**；Start 可能擦除当前 overlay/会话 |
| `localization` | 参考地图 Load、定位 Session Start/Stop/Reset、Tracking/Reloc | `localization Load` 才用于**定位参考 PCD**；Start/Reset 会切换角色/停止建图 |
| `octomap` | Octomap Save/Reset/输入开关 | Reset、Disable 可能清图或中断输入 |
| `bag` | rosbag 录制、回放、暂停/Fresh session | 回放时钟切换和 Fresh session 会影响整个系统 |
| `viz` | RViz Ego/World、关闭显示窗口 | `Close all` 可能关闭本机所有 RViz，非仅当前窗口 |
| `debug` | 诊断、适应度、配置与调试 | 部分控制会改变诊断或算法运行设置；缺少服务时可能超时 |

GUI 上 **`Publish once / Publish regularly` 主要控制地图可视化话题**（如 `/localization_map`），不等同于启动定位，也不决定 `/robot_pose` 是否有效。

## 4. 定位标准流程（本轮仅学习，不执行）

以下步骤属于**以后经负责人批准后**的操作 SOP；不能直接在当前运行设备上点击。

### 4.1 前置条件

1. 确认已安装并运行**单一**正确的 SLAM Console，后端 `slam3d_node` 在运行，GUI 服务可达。
2. 已有**真实可读、场景匹配**的 `.pcd` 固定参考地图，记录完整路径、来源、坐标系和版本；不要假设 SDK 默认 `/root/resources_storage/cloud_map_pgo.pcd` 在机器人上真实存在。
3. `/livox/lidar/geo_filtered` 有连续点云，QoS 与订阅一致；静态 TF 到 `lidar_link` 正确。
4. 记录当前外层角色和会话，确认是否在建图；如果正在建图，先经人工确认是否已保存地图，因 Loc Start / Reset 可能先停止建图。
5. 已知 `base_footprint→base_link` 双 RSP 冲突未解决时，**不能将定位输出用于真机速度放行或正式验收**。

### 4.2 GUI 定位流程及预期状态

| 阶段 | GUI/系统动作（获授权后） | 需要验证的证据 |
|---|---|---|
| A | 进入 `localization` 标签 | 确认操作的是定位页，不是 mapping 的地图 Load |
| B | 在定位 Map 栏选 `.pcd` 执行 `Load from disk` | GUI Log 返回成功；`/localization_status` 的 `config_context_map_loaded=true` |
| C | `Control → Session Start` | 新版 GUI 按需经 `Stop → Idle → enter_localization → load_map → start_localization → enter_relocalization`；状态变为外层 Localization、内层 Relocalization、处理使能 |
| D | 观察 Relocalization / 配准质量，必要时使用 `/initialpose` | 先记录适应度、配准状态、TF 与扫描输入；`/initialpose` 只在支持的重定位状态下生效，TF 转换失败则可被拒绝 |
| E | 配准结果可信后进入 Tracking（可能需要显式 `Mode enter_tracking`） | 新版 YAML `localization.enable_automatic_mode_switch=false`，不能默认自动切换；不能仅靠点击 Tracking 证明定位可靠 |
| F | 验收定位输出 | `/robot_pose` 有连续有效数据，`map→tracking_frame` TF 可用且稳定，`/localization_status` 的定位质量/会话标志正常 |

**版本差异**：旧 PDF 通常将 `localization → Load from disk → Session Start` 作为简化流程；**新版 GUI 的 Loc Start 内含外层角色切换和服务序列**。详细操作/异常恢复以新版 `manual_console_slam3d.md` 和运行时 GUI 日志为准。

### 4.3 不能混淆的三个判断

- **`/localization_status` 有消息**：只证明状态通道在报告，不代表已经定位。新版状态在 Idle 时仍能发布。
- **`config_context_map_loaded=false`**：意味着定位参考地图未加载成功/未在当前状态中建立，常见于 Idle 尚未执行 Load，不应直接写成“甲方定位故障”。
- **`/robot_pose` 有消息**：说明位姿产品正在发布，但并不自动证明 ICP/NDT 已收敛、已进入 Tracking 或精度合格。

## 5. 只读定位诊断清单

在甲方 ROS 环境有效时执行。以下命令**只查询，不调用任何状态改变服务**：

```bash
export ROS_DOMAIN_ID=55
export FASTDDS_BUILTIN_TRANSPORTS=UDPv4
source /home/demo/release_slam_3d/setup_runtime.sh

# 环境与参与者
ros2 node list
ros2 service list | grep -E 'slam3d_node|lidar_cloud_preprocess'
ros2 topic list | grep -E 'odom|livox|robot_pose|localization_status|mapping_status|/tf'

# 定位状态——最可靠的运行时来源（服务设置可能不会反映到 ros2 param get）
ros2 topic echo /localization_status --once
ros2 topic echo /localization_status --once --field config_context_map_loaded
ros2 topic echo /localization_status --once --field control_signal_enable_processing

# 位姿是否真的发布；如当前没有数据，8 秒后自动退出
 timeout 8 ros2 topic echo /robot_pose --once

# 查询发布者/订阅 QoS（注意不要把 Publisher count 当真实数据）
ros2 topic info /odom -v
ros2 topic info /livox/lidar -v
ros2 topic info /livox/lidar/geo_filtered -v

# 坐标变换可用性（首次 tf2_echo 需要暖机，且不能只看第一次结果）
timeout 8 ros2 run tf2_ros tf2_echo base_link lidar_link
timeout 8 ros2 run tf2_ros tf2_echo base_link livox_frame
timeout 8 ros2 run tf2_ros tf2_echo base_footprint base_link
```

**若某条命令因 ROS CLI 加载错误失败**：先检查 `source` 是否成功、`LD_LIBRARY_PATH` 是否包含 `/opt/ros/humble/lib`，再判断是否数据不通。曾观察到未正确 source 导致 `librcl_action.so` 缺失，不能将此种 CLI 崩溃报告为“甲方所有 Topic 消失”。

### 5.1 状态—原因—下一步核查（不自动修复）

| 观察 | 优先核查方向 |
|---|---|
| GUI 打开、`slam3d_node` 存在，但 `map_loaded=false`、`/robot_pose` 无消息 | 正常可能处于 Idle/Stopped；先核对是否加载定位 PCD、GUI Log 是否成功、角色/会话是否启动 |
| `map_loaded=true`、`enable_processing=false` | 地图虽有，但定位会话可能未 Start 或处于 Stopped |
| `enable_processing=true`、无 `robot_pose` | 检查扫描、位姿发布前置条件、TF、配准结果、会话状态及日志，不能直接归因 TF |
| `/robot_pose` 出现但 Tracking 未就绪 | 查看 Relocalization、fitness、`registration_output_*`、`/initialpose` 和自动模式切换开关 |
| GUI 控件服务超时 | 对照新版服务清单；部分旧 GUI YAML 键可能指向未实现服务 |
| `tf2_echo` 多次得到不同外参 | 检查重复静态 TF 发布者及不同 URDF，而不是复制第三条 TF 掩盖 |

**新版运行时关键字段**（从 `ros2 topic echo /localization_status --once` 的实际类型/输出核对，不能照抄旧版字段名）：

- `control_signal_outer_role`：Idle / Mapping / Localization 外层角色（如当前消息实际具有该字段）。
- `config_context_map_loaded`：固定参考地图是否加载。
- `control_signal_enable_processing`：当前是否开启定位处理。
- `control_signal_session_mode`：内层会话状态，实际名称与枚举从机器人消息类型核对。
- `registration_output_localization_mode`、`registration_output_fitness_mse`、`registration_output_pose_published`、`registration_output_tf_published`：配准和发布状态。

以上是**字段核查方向**，请用现场 `ros2 interface show hivecore_slam3d/msg/LocalizationStatus` 与实际输出确定完整字段，防止跨版本误解。

## 6. Motion Runtime / SDK：必须掌握的接口及禁令

### 6.1 当前新 SDK 的接口契约（依据 `config/api_contract.yaml`）

| 接口 | 类型 | 用途 | 当前权限 |
|---|---|---|---|
| `/odom` | `nav_msgs/msg/Odometry` | 里程计 | 只读 |
| `/chassis_state` | `interfaces/msg/ChassisState` | 底盘状态 | 只读 |
| `/livox/lidar` | `sensor_msgs/msg/PointCloud2` | Livox 原始点云；实际消息格式还应现场核对 | 只读 |
| `/cmd_wheel` | `geometry_msgs/msg/Twist` | SDK/遥控上游速度输入，经 preprocessor 至 `/cmd_vel` | **禁发** |
| `/cmd_vel` | `geometry_msgs/msg/Twist` | 下游物理速度接口；受控模式细节以现场运动栈为准 | **禁发** |
| `/chassis_dec_stop` | `std_msgs/msg/Empty` | 底盘减速停止控制 | 禁止“试一下” |
| `/estop` | `std_msgs/msg/Bool` | 急停相关控制 | 禁止“试一下” |
| `/set_chassis_enable`、`/clear_chassis_error` | 自定义服务 | 使能、清错 | 禁调 |
| 轮腿 Action（MoveLeg/Home/Joint）、腿使能、平衡 | Action / Service | 腿部运动或状态变更 | 禁调 |
| `/battery_state` | `sensor_msgs/msg/BatteryState` | 电池 | 只读 |

**重要版本差异**：旧 Hive2 PDF 提到 `/chassis_control_mode` 和 `/dec_stop`，而新 Motion Runtime `overview.md` 标记旧的 `chassis_control_mode` 已取消，新的契约使用 `/chassis_dec_stop`、`/estop`。不可假定旧 Web 模式切换流程适用于当前版本。

**重要里程计区别**：新 Motion Runtime `overview.md` 还列出 `/odom_fusion` 作为导航里程计，而本次现场乙方已实测 `/odom`（`odom/base_link`）连续发布。学习时需只读比较两者的发布者、`frame_id`、`child_frame_id`、速率、TF 来源，不能擅自将 M1 的 `/odom` 改为 `/odom_fusion`。

### 6.2 SDK 示例存在真实运动代码

`docs/getting_started.md` 中 Python `HiveChassisClient.set_velocity(vx=0.1)`、C++ `ChassisClient::set_velocity(...)` 都是**可执行的运动指令**，本阶段绝对禁止执行。也不要运行自带 `example_move_chassis_cpp` 等示例，即便仅为“验证 SDK 安装”。

底盘通信还可能有 Web、手柄、导航等多源同时影响速度的情况。运动栈说明提到多源写入时存在覆盖风险，必须将速度控制的授权和互斥设计作为后续独立专项，不在本轮完成。

### 7.2 QoS 与数据语义

- 新版 `hivecore_cloud_preprocessor` 的 `/livox/lidar/geo_filtered` 使用 `SensorDataQoS / Best Effort`；现场 `/livox/lidar` 的发布端为 Reliable。订阅要检查实际 QoS，不能只看 Topic 名。
- 过滤点云是否有数据可能受 `enable_forward` 和订阅者数量影响。不要点击 `Cloud forward Disable` 作测试。
- SLAM 正式扫描输入在新版配置中为 `/livox/lidar/geo_filtered`，`scan_frame=lidar_link`。
- SDK/预处理链中静态 TF 至少涉及 `base_link→lidar_link→imu_link→livox_frame`。实时系统里应核对坐标变换的**完整旋转和平移**，不能仅用三个平移分量认定标定正确。

### 7.3 HC-INT-001：双 RSP 静态 TF 冲突（已验证）

`base_footprint→base_link`：

- 运动栈 `hive2.config.xacro`：Z=0.900m。
- GUI-SLAM `hivecore_robot.urdf.xacro`：`footprint_xyz` 默认 Z=0.300m。
- 独立 `tf2_echo` 多次采样曾观察到 0.9/0.3 交替。**两套变换值不同属确证**。

新版 `manual_robot_description.md` 还说明其 RSP 被 Console 的 `preprocessing.launch.py` 包含，默认 `footprint_xyz=0 0 0.3`；甲方运动栈的正确几何、两套变换的权威发布权仍需甲方确认。不要通过新增 `/tf` 补边、覆盖高度或更改脚本掩盖冲突。

`ros2 topic info /tf_static -v` 的**总发布者数量不是同一条 TF 边的发布者数量**；曾观察到 3 个发布者，但冲突 RSP 是其中的两个，另有正常的静态 TF 发布节点。必须按具体 `parent_frame → child_frame` 取证。

### 7.4 M1 与定位模式的边界

- **M1 `/odom` 相对导航验证**：核心输入为里程计、点云及对应静态外参。乙方最新版部分节点已直接消费 `/odom`，不是所有模块都要求 `/robot_pose`。**2026-10-14 起乙方默认点云输入为 `/livox/lidar/geo_filtered`**（原始 `/livox/lidar` 仅显式可选，且需确认其 frame TF）。
- **地图定位模式**：依赖有效 PCD、GUI Localization 会话、定位位姿与 `map` 系 TF，并要求验证定位质量。
- 双 RSP 冲突**不等价于数据断流**；但目前约定它阻断导航干跑准入及正式验收。无需为了“证明能接收点云”临时绕过安全门禁。
- 乙方 Preflight 脚本已提交不代表无缺陷；2026-10-14 已修复 TF 假阳性（tf_ok 纯空白判为非空）与 `/tf_static` 发布者总数误计（应为 2×robot_state_publisher，static_tf_publisher_node 不计入冲突）。学习阶段不把脚本的单一 PASS/FAIL 当作甲方故障的唯一证据。

### 8.1 常见误区与正确处理

1. **“GUI 已启动，所以应有 `/robot_pose`”——错误。** 新版 GUI Console 默认 Idle，内层停止。先查地图/角色/会话。
2. **“有 `/localization_status` 就定位成功”——错误。** Idle 也可能持续发布状态。
3. **“地图 Publish 打开就会定位”——错误。** 它是地图可视化产品。
4. **“点 `mapping Load` 就能用于定位”——错误。** `mapping Load` 是 overlay；定位参考图应在 Localization 侧加载。
5. **“Session Start 等于 Tracking 成功”——错误。** 它通常先进入 Relocalization；新版自动切换默认关闭。
6. **“没看到 `ros2 topic list` 就是甲方没发”——错误。** 先排除未 source、域号和 `LD_LIBRARY_PATH` 错误。
7. **“`/tf_static` 有三名发布者就代表三名冲突”——错误。** 分边识别。
8. **“绕过 preflight 做 Dry-run 无底盘输出所以无需批准”——错误。** 违反本阶段用户授权边界。
9. **“官方 SDK 示例只是 demo，可以随便跑”——错误。** 部分示例会直接发运动指令。
10. **“把旧版文档命令直接在新版机器上执行”——错误。** 先比对新版实际包名、服务和接口。
